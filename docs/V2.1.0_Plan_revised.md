# ReactionProfileHunter V2.1.0 Revised Plan（S1 四协议 Funnel + Shared DFT Handoff 实施蓝图）

> **文档定位**：本文件是 `docs/V2.1.0_Plan_full.md` 的修订深化版，基于 2026-04-10 的代码复核、运行语义复核、S2/S3/S4 下游契约复核，以及 CENSO 参考调研，给出 **可直接进入开发阶段** 的 S1 四协议逐文件实施 blueprint。
>
> **核心修订点**：
>
> 1. 不再把 `lite/zero` 理解为“最终交付层级较低”的协议；
> 2. 正式采用 `ext/full/lite/zero = funnel policy`，`shared DFT handoff = shared finalization layer`；
> 3. 下一阶段的目标不是修补若干 flag，而是把 S1 的运行时结构升级到可以承载四协议语义。

---

## 1. 执行摘要

当前仓库中的 S1 真实形态是：

- `ConformerEngine.run()` 基本执行一条固定主线；
- `ProtocolSpec` 仍是轻量元数据对象；
- `final_opt_sp.py` 只支持“全量 / 取第一个”；
- `full` 协议显式未实现；
- orchestrator / S2 / S4 依赖统一的 S1 工件契约，而不是协议内部细节。

因此，V2.1.0 的正确落地方式不是继续给 `lite/zero` 打补丁，而是建立下面这个正式结构：

```text
protocol = funnel policy
shared_handoff = DFT OPT/FREQ/SP shared finalization layer
downstream = always consume DFT-level artifacts
```

这意味着：

- `ext`：最贵、最稳，参考基线；
- `full`：CENSO-default-like，多 survivor DFT handoff；
- `lite`：经济 funnel，单最优或 top-2 fallback DFT handoff；
- `zero`：最便宜 funnel，rank1 或极窄窗口 DFT handoff；
- **四者最终都交付统一层级的 DFT 工件给 S2/S3/S4。**

---

## 2. 本次修订后的非协商约束

以下内容在下一阶段必须保持稳定：

1. `S1_ConfGeneration/product_min.xyz` 仍是 S1 → S2 的 canonical product geometry。
2. `provenance.json` 仍由 `AnchorPhase` 写出，且下游可无痛读取旧字段。
3. `artifact_contract.product_geometry_level` 仍表示 **最终交付层级**，而不是 funnel 层级。
4. `conformer_energies.json` 继续表示 **final DFT handoff energies**，不能被重载为 xTB funnel 排名文件。
5. `product_log / product_fchk / product_qm_output / product_thermo` 仍是统一的 S1 对下游 QC 工件槽位。
6. `has_geometry_optimization` 在四协议落地后应真实且稳定地反映 shared DFT handoff 是否成功。

## 3. 目标协议语义（正式版）

### 3.1 ext

定位：RPH 内部 reference baseline。

流程：

`RDKit -> CREST two-stage (GFN0->GFN2) -> ISOSTAT / dedup -> keep all candidates -> DFT OPT/FREQ for all -> high-level SP -> Shermo -> Boltzmann -> final minimum`

handoff mode：`optimize_all_candidates`

### 3.2 full

定位：CENSO-default-like multi-stage funnel + multiple survivor DFT handoff。

流程：

`RDKit -> CREST GFN2 -> clustering -> prescreening low-cost DFT SP -> screening r2SCAN-3c SP + mRRHO-like correction -> survivors within window -> DFT OPT/FREQ for survivors -> high-level SP -> Boltzmann -> final minimum`

handoff mode：`optimize_all_survivors_within_window`

### 3.3 lite

定位：经济 funnel + 单最优候选 DFT handoff。

流程：

`RDKit -> CREST GFN2 -> clustering -> r2SCAN-3c SP rerank -> optional GFN2 mRRHO-like correction -> rank1 -> top2 fallback if gap small -> DFT OPT/FREQ -> high-level SP -> final minimum`

handoff mode：`optimize_rank1`

fallback：`optimize_top2_if_gap_small`

### 3.4 zero

定位：最便宜 funnel + 极少候选 DFT handoff。

流程：

`RDKit or minimal GFN2 -> GFN2 ranking -> narrow-window selection -> rank1 or all within 0.5 kcal/mol -> DFT OPT/FREQ -> high-level SP -> final minimum`

handoff mode：`optimize_rank1`

fallback：`optimize_all_within_0p5_kcal`

---

## 4. 目标架构图

```text
AnchorPhase
  -> resolve ProtocolSpec
  -> create_s1_engine(protocol_spec)

ConformerEngine.run()
  1. RDKit embed
  2. protocol funnel
  3. CandidateSet
  4. shared handoff candidate selection
  5. shared DFT OPT/FREQ/SP closure
  6. product_min.xyz + provenance.json + QC artifacts

S2 / S3 / S4
  -> remain blind to funnel internals
  -> consume canonical S1 artifacts only
```

### 当前状态

新增或重组以下层级：

```yaml
step1:

    enabled: true
    dft_optfreq: true
    opt_method: B3LYP-D3(BJ)
    opt_basis: def2-SVP
    final_sp: true

  protocol_stack:
    ext:
      two_stage_enabled: true
      ngeom_default: 3
      ngeom_max: 6
      funnel:
        search_mode: crest_two_stage_gfn0_to_gfn2
        clustering_mode: isostat
        prescreen_mode: none
        rerank_mode: none
      handoff:
        mode: optimize_all_candidates
        fallback_mode: none
        ranking_after_handoff: shermo_plus_sp_boltzmann

    full:
      two_stage_enabled: false
      ngeom_default: 12
      ngeom_max: 24
      funnel:
        search_mode: crest_gfn2
        clustering_mode: isostat
        prescreen_mode: low_cost_dft_sp
        rerank_mode: r2scan3c_sp_plus_mrrho
        survivor_window_kcal: 3.0
      handoff:
        mode: optimize_all_survivors_within_window
        fallback_mode: none
        ranking_after_handoff: final_sp_plus_boltzmann

    lite:
      two_stage_enabled: false
      ngeom_default: 6
      ngeom_max: 12
      funnel:
        search_mode: crest_gfn2
        clustering_mode: isostat
        prescreen_mode: none
        rerank_mode: r2scan3c_sp
        use_mrrho_like_correction: true
      handoff:
        mode: optimize_rank1
        fallback_mode: optimize_top2_if_gap_small
        small_gap_kcal: 1.0
        ranking_after_handoff: final_sp_minimum

    zero:
      two_stage_enabled: false
      ngeom_default: 4
      ngeom_max: 8
      funnel:
        search_mode: crest_gfn2_or_skip
        clustering_mode: minimal
        prescreen_mode: none
        rerank_mode: gfn2_energy
        narrow_window_kcal: 0.5
      handoff:
        mode: optimize_rank1
        fallback_mode: optimize_all_within_0p5_kcal
        ranking_after_handoff: final_sp_minimum
```

### 注意事项

- `default` 建议暂时保留为 `ext` 的 alias，但文档不再把它列为主要协议；
- 不再把 `freq` 作为 lite/zero 的核心差异字段；
- 四协议共享 `shared_handoff.dft_optfreq = true`。

### 验收门

- `step1.protocol: full` 能正常解析；
- ext/full/lite/zero 均有显式 funnel/handoff 配置；
- 配置文件注释能解释“协议差异在 funnel，不在 final handoff layer”。

## 5.2 `rph_core/steps/conformer_search/protocols.py`

### 当前状态

- `ProtocolSpec` 仍是 flag 集合；
- `full` 被写死为未实现；
- `selection_mode` 语义不足以表示目标 handoff 规则。

### 目标状态

升级为 protocol runtime authority。

### 拟新增 dataclass

```python
@dataclass(frozen=True)
class FunnelPolicy:
    search_mode: str
    clustering_mode: str
    prescreen_mode: str
    rerank_mode: str
    use_mrrho_like_correction: bool
    survivor_window_kcal: Optional[float]
    narrow_window_kcal: Optional[float]


@dataclass(frozen=True)
class HandoffPolicy:
    enabled: bool
    mode: str
    fallback_mode: Optional[str]
    small_gap_kcal: Optional[float]
    ranking_after_handoff: str


@dataclass(frozen=True)
class ProtocolSpec:
    name: str
    two_stage_enabled: bool
    ngeom_default: int
    ngeom_max: int
    funnel_policy: FunnelPolicy
    handoff_policy: HandoffPolicy
    provenance_flags: Dict[str, bool]
    raw_config: Dict[str, Any]
```

### 拟新增函数

```python
def resolve_protocol_spec(config: Dict[str, Any], protocol: str) -> ProtocolSpec: ...
def _resolve_funnel_policy(step1_cfg: Dict[str, Any], protocol_name: str) -> FunnelPolicy: ...
def _resolve_handoff_policy(step1_cfg: Dict[str, Any], protocol_name: str) -> HandoffPolicy: ...
def as_provenance_payload(spec: ProtocolSpec) -> Dict[str, Any]: ...
```

### 修改要点

1. 去掉 `UNIMPLEMENTED_PROTOCOLS = {"full"}`；
2. 让 `resolve_protocol_spec()` 显式解析四协议；
3. `ProtocolSpec` 不再负责直接决定 Gaussian route，而是决定 funnel 与 handoff 行为；
4. 保留 `raw_config` 用于 provenance / debug。

### 验收门

- `full` 可解析；
- serialize 后能看见 `funnel_policy` 与 `handoff_policy`；
- `ProtocolSpec` 可直接作为测试 fixture 使用。

## 5.7 `rph_core/steps/conformer_search/engine.py`

### 当前状态

`run()` 基本固定为：

`RDKit -> CREST -> _step_process_ensemble -> _run_final_opt_sp_stage -> product_global_min.xyz`

### 目标状态

变成：

```python
def run(self, smiles: str) -> Tuple[Path, float]:
    initial_xyz = self._step_rdkit_embed(smiles)
    candidate_set = self._run_protocol_funnel(initial_xyz)
    best_log, min_energy, stage_meta = self._run_shared_dft_handoff(candidate_set)
    global_min_path = self._materialize_global_min(best_log, min_energy)
    return global_min_path, min_energy
```

### 拟新增字段

```python
self.funnel_policy = self.protocol_spec.funnel_policy
self.handoff_policy = self.protocol_spec.handoff_policy
```

### 拟新增方法

```python
def _run_protocol_funnel(self, initial_xyz: Path) -> CandidateSet: ...
def _run_ext_funnel(self, initial_xyz: Path) -> CandidateSet: ...
def _run_full_funnel(self, initial_xyz: Path) -> CandidateSet: ...
def _run_lite_funnel(self, initial_xyz: Path) -> CandidateSet: ...
def _run_zero_funnel(self, initial_xyz: Path) -> CandidateSet: ...
def _build_candidate_set_from_ensemble(self, ensemble_file: Path, *, ranking_basis: str, source_stage: str) -> CandidateSet: ...
def _run_shared_dft_handoff(self, candidate_set: CandidateSet) -> Tuple[Path, float, Dict[str, Any]]: ...
def _materialize_global_min(self, best_log: Path, min_energy: float) -> Path: ...
```

### `_step_dft_opt_sp_coupled()` 的定位

保留为 shared DFT closure，不再让其做协议判断。

其职责固定为：

1. 对传入候选逐个做 Gaussian OPT/FREQ；
2. 做高层 SP；
3. 跑 Shermo；
4. 生成 DFT-level record list；
5. 选择 handoff 后 final minimum。

### 注意事项

- 不要把 xTB funnel 排名写进 `conformer_energies.json`；
- 若需保留 funnel ranking，新增 `funnel_candidate_summary.json`；
- `run_optimization_only()` 也要统一走 shared handoff closure，只是 funnel 极简化。

### 验收门

- ext 先通过新 handoff 路径跑通，行为与旧主线等价；
- full/lite/zero 再逐一接入。

## 9. 风险与回退策略

### 风险 1：协议语义变化引发旧测试失真

处理：

- 不立即删除旧测试；
- 分阶段替换 `zero` 旧语义断言；
- 在 Phase D 前保留过渡性兼容说明。

### 风险 2：resume 误复用

处理：

- 在 `state_manager.py` 中加入 protocol/handoff signature；
- rollout 前先实现 resume compatibility check。

### 风险 3：S4 错把 funnel ranking 当 final energy

处理：

- `conformer_energies.json` 继续保留 final DFT 语义；
- funnel ranking 单独写新文件。

## 10. 最终结论

下一阶段最重要的不是“修一个 lite/zero bug”，而是：

> **把当前单路径 S1 引擎，升级为可承载四协议 funnel policy + shared DFT handoff 的运行时结构。**

正确的推进顺序是：

1. 先冻结 shared handoff；
2. ext 先迁移；
3. 再实现 full；
4. 再实现 lite；
5. 最后实现 zero 并修正链路测试语义；
6. 全程保持 downstream artifact contract 稳定。

只有这样，V2.1.0 的四协议系统才会是**可解释、可回归、可发表描述、可下游稳定消费**的一套正式机制，而不是继续堆叠在旧 `ConformerEngine` 上的局部补丁。
