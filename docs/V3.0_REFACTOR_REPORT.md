## 1. 重构目标

将 RPH V2.1.1 单体仓库拆分为三个职责清晰的独立包：

| 包 | 职责 | 代码量 |
|---|---|---|
| **rph_core** | S0–S3 机理计算 | 120 .py, 42,283 行 |
| **rph_features** | S4 热力学 + 特征提取 | 42 .py, 9,633 行 |
| **rph_ml** | 模型训练 | 7 .py, 6,485 行 |
| **rph_schemas** | 共享 schema/列定义 | 3 .py |

同步清理源码树中的输出文件、备份、过期文档、废弃测试和重复功能。

### Phase 7: 收敛重复功能

#### 7a: 统一 is_toxic_path

**问题：** `is_toxic_path()` 在两个文件中重复定义，逻辑完全相同。

| 文件 | 函数名 | 状态 |
|------|--------|------|
| `rph_core/utils/path_compat.py:38` | `is_toxic_path()` | ✅ 唯一定义 |
| `rph_core/utils/qc_interface.py:1437` | `is_path_toxic()` | 已改为别名导入 |

**变更：**
- `qc_interface.py` 删除重复定义 (22 行)，改为 `from rph_core.utils.path_compat import is_toxic_path as is_path_toxic`
- `gau_xtb_interface.py` 改为从 `path_compat` 导入
- `rph_features/mech_packager.py` 改为从 `path_compat` 导入
- 测试文件 monkeypatch 目标 `qc_interface.is_path_toxic` 仍然有效 (指向别名)

#### 7b: Forming Bonds 单一来源文档

在 `rph_core/utils/forming_bonds_resolver.py` 顶部添加了 Single Source of Truth 文档块：

```
来源链 (优先级从高到低):
1. S2_Retro → forming_bonds in mechanism_meta.json
2. S3_TS/mechanism_meta.json → 从 S2 传递
3. package_manifest.json → 持久化的 forming_bonds
4. Legacy fallback: config/SMARTS 自动检测
```

消费者 (rph_features) 应优先从 manifest 读取，仅在缺失时走 legacy fallback。

#### 7c: 创建 rph_schemas 共享包

```
rph_schemas/
├── __init__.py           # 导出 FIXED_COLUMNS, FEATURE_COLUMNS, ARTIFACT_CONTRACT
├── feature_schema.py     # 特征列名常量 (从 rph_features/schema.py 提取)
├── artifact_schema.py    # 各步骤期望输出文件清单
└── README.md
```

- `rph_features/schema.py` 现在优先从 `rph_schemas` 导入，带有 fallback
- `rph_ml` 也可从 `rph_schemas` 读取列定义，避免硬编码重复

## 6. 已知问题与后续工作

### 需要修复的预存测试

1. **test_s3_ts_rescue_policy.py** (6 failures)
   - mock 补丁目标不匹配，需要更新 `@patch` 路径

2. **test_s4_mech_packager.py / test_s4_v62_final_verification.py** 等 (74 failures)
   - mech_packager 行为与测试期望不一致
   - 建议在 rph_features 包稳定后统一修复

### 后续拆分方向

1. **rph_features 完全独立化**
   - 当前 rph_features 仍有 33 处 `from rph_core.utils.*` 导入
   - 长期目标：将共享 utils 提取为 `rph_utils` 包，三个包都依赖它

2. **三仓库分离**
   - rph_core → ReactionProfileHunter (主仓库)
   - rph_features → rph-features (可独立成仓库)
   - rph_ml → rph-ml (可独立成仓库)

3. **package_manifest.json 规范化**
   - 定义 RPH core 输出的标准化 manifest
   - rph_features 从 manifest 读取所有元数据，不再依赖目录结构推断

4. **热力学计算统一**
   - 当前散布在 rph_core/utils/thermo/, rph_features/thermo/, shermo_runner.py
   - 统一到 rph_features/thermo/，rph_core 不再生成条件级 feature table
