> 更新日期：2026-04-12  
> 对齐文档：`docs/V2.1.0_Plan_revised.md`、`docs/V2.1.0_Plan_full.md`

## 1. 报告摘要

ReactionProfileHunter（RPH）当前已经形成一个完整的 **product-driven 反应机理搜索与特征提取流水线**，主线流程为：

```text
输入 SMILES / 数据集记录
    → S0 机理分类
    → S1 多构象锚定
    → S2 逆向扫描与 TS 初猜
    → S3 TS 优化 / 验证
    → S4 特征提取
```

V2.1.0 三项最重要新增能力已全部落地：

1. **S0 机理分类**：将成键拓扑从猜测提升为显式机理前置步骤  
2. **S1 协议化多构象搜索**：支持多种预算等级的构象 funnel 策略  
3. **S2 逆向扫描链路**：`retro scan + path search + Gau_XTB` 稳定生成 TS 初猜  

当前最准确的项目判断可以概括为：

> **RPH 已从"单步产物驱动搜索脚本"演化为具备机理感知、协议配置、可恢复执行、可扩展特征挖掘能力的完整平台。**

## 3. 三大新增能力详解

### 3.1 S0 阶段：机理分类实现

#### 3.1.1 定位

S0 的定位不是量化计算，而是 **机理结构化**。  
其主要职责是把输入记录转换为 `MechanismGraph` DAG，并输出权威的 `forming_bonds` 给 S2。

#### 3.1.2 已支持反应类型

| **类型** | **机理模型** |
|---|---|
| `[4+3]`、`[5+2]` | 两步机理（stepwise） |
| `[4+2]`、`[3+2]` | 单步机理（concerted） |

#### 3.1.3 核心文件

- `rph_core/steps/mechanism_classifier/classifier.py`
- `rph_core/steps/mechanism_classifier/models.py`
- `rph_core/steps/mechanism_classifier/graph_builder.py`
- `rph_core/steps/mechanism_classifier/clean_adapter.py`

#### 3.1.4 当前产出结构

`mechanism_summary.json` 当前主要包含：

- `reaction_id`
- `reaction_type`
- `cyclo_mode`
- `topology`
- `forming_bonds`

其中最关键字段是：

- **`forming_bonds`**

#### 3.1.5 当前价值

S0 已将"形成哪些键"从以下方式：

- SMARTS 猜测
- 几何反推
- 配置手填

提升为：

- **显式、统一、可持久化的机理前置步骤**

#### 3.1.6 当前局限

| **缺失能力** | **影响** |
|---|---|
| 反应物 / 中间体 / 副产物的完整配平表达 | 无法计算真正平衡热力学 |
| `leaving group / oxidant / byproduct` 显式节点 | DMDO 等氧化剂无法正确计入 |
| 每一步的 `stoichiometry` | 多碎片体系会出错 |
| `dr / endo / exo` 的路径展开 | 无法支持立体化学预测 |
| `_infer_intermediate_smiles()` 返回 `None` | 中间体结构需后续阶段补足 |

#### 3.1.7 小结

> **S0 已实现"成键拓扑级机理分类"，但尚未实现"热力学完备的机理语义层"。**

---

### 3.2 S1 阶段：多构象搜索协议配置

#### 3.2.1 定位

S1 的目标是把前体 / 产物 / 小分子锚定到低能构象，并形成可配置、可复现的协议化 funnel。

#### 3.2.2 支持的协议

| **协议** | **策略** | **适用场景** |
|---|---|---|
| `ext / default` | CREST 两阶段（GFN0 → GFN2）→ 全量 handoff → DFT | 高精度 |
| `full` | GFN2 → `PBEh-3c` → `r2SCAN-3c` → survivor → DFT | 平衡精度 / 成本 |
| `lite` | GFN2 → `r2SCAN-3c` → rank1 handoff → DFT | 快速筛选 |
| `zero` | GFN2 → xtb-energy funnel → 窄窗口 handoff → DFT | 最低成本 |

#### 3.2.3 核心文件

- `rph_core/steps/anchor/handler.py`
- `rph_core/steps/conformer_search/engine.py`
- `rph_core/steps/conformer_search/protocols.py`
- `rph_core/utils/small_molecule_cache.py`

#### 3.2.4 当前价值

S1 已实现：

1. 搜索协议显式化  
2. 低成本 funnel 与高精度 handoff 分离  
3. 同一引擎承载不同预算模式  
4. baseline / CENSO-like / fast-SP / cheap 等模式并存  

#### 3.2.5 缓存现状

- ✅ 小分子（重原子数阈值以下）已缓存复用  
- ❌ 主产物 / 主前体的大分子未缓存  

#### 3.2.6 小结

> **S1 已完成从"单一构象搜索流程"到"协议化 funnel runtime"的升级，但缓存范围仍主要局限于 small molecule。**

---

### 3.3 S2 阶段：逆向扫描策略实现稳定 TS 搜索

#### 3.3.1 核心思想：Retro Outward Scan

S2 的方法学核心是：

> 从产物态的短键距离开始，沿逆反应方向拉伸 `forming_bonds`，追踪能量曲线，并在能量峰值附近定位 TS 候选。

```text
产物态 (短键: ~1.8 Å)
    → 扫描
    → 反应物态 (长键: ~3.5 Å)
                  ↑
             TS 出现在能量峰值附近
```

#### 3.3.2 优势

- 产物几何已知且更可靠
- 成键坐标明确定义
- 更容易围绕 barrier 区域追踪能量变化

#### 3.3.3 关键算法组件

| **组件** | **功能** | **文件** |
|---|---|---|
| 约束策略 | Policy C：双 `forming bond` 弱谐和约束 | `scan_policies.py` |
| Knee-point 检测 | 基于曲率 / 折点定位 TS 候选 | `scan_profile_plotter.py` |
| Topology Guard | 检测扫描轨迹是否偏离反应坐标 | `geometry_guard.py` |
| Gau_XTB 预优化 | 提升 TS 初猜质量 | `gau_xtb_interface.py` |
| Path Search | `xTB --path` 路径搜索，与 retro scan 互补 | `retro_scanner.py` |

#### 3.3.4 默认扫描参数

- `start_distance`: ~1.8 Å
- `end_distance`: ~3.5 Å
- `steps`: ~20

#### 3.3.5 当前价值

S2 已形成一套完整的 TS 初猜稳定化组合链：

```text
S0 forming_bonds
    ↓
retro scan → 能量剖面
    ↓
knee-point → TS 猜测
    ↓
topology guard → 轨迹验证
    ↓
Gau_XTB / path search → 二次增强
    ↓
高质量 TS 初猜 → S3
```

#### 3.3.6 小结

> **S2 已经不是单纯的扫描步骤，而是集成了成键约束、能量剖面分析、轨迹校验与二次增强的 TS 初猜稳定化模块。**

## 5. 当前系统的关键短板

### 5.1 缓存只覆盖小分子，不覆盖重复主分子

当前以 `rx_id` 为目录主键，同一分子出现在多条记录时会重复计算：

```text
rx_001: product_smiles_main = "C1=CC=CC=C1" → 跑完整 S1/S2/S3
rx_002: product_smiles_main = "C1=CC=CC=C1" → 再跑一遍
rx_003: ... → 再跑一遍
```

**影响：** 批量任务计算成本成倍放大。

---

### 5.2 `dr / ee` 已解析但未进入主流程

**现状：**

- 数据层已能读取 `ee`、`dr_major`、`dr_minor`
- 主流程基本没有消费这些信息

**后果：**

- 数据表里已有 stereochemical outcome 信息
- 流水线尚未将其转为显式路径展开或标签学习对象

---

### 5.3 S0 没有输出完整配平机理表达式

当前缺失：

- 每一步反应物清单
- 副产物清单
- `oxidant / leaving group / catalyst / byproduct` 的角色区分
- `stoichiometric coefficient`
- `balanced step equation`

---

### 5.4 S4 第一步热力学不完备

当前实现近似为：

```text
dG_act = G(S3_intermediate) + G(leaving_group) - G(precursor)
```

且 `leaving_group` 获取逻辑明显偏向 HOAc。

对于 DMDO 氧化体系，实际第一步更接近：

```text
Precursor + DMDO → Ylide + Acetone
```

而当前近似成：

```text
Precursor → Intermediate + HOAc-like leaving group
```

导致漏掉：

- oxidant 消耗
- byproduct 生成
- 多碎片 stoichiometry
- 第一步真实热力学闭合

### 5.5 小结

> **当前系统的核心短板，已经不是"能不能跑通"，而是"能否避免重复计算、能否表达完整机理、能否输出真正平衡的热力学特征"。**

## 6. V2.2 升级计划

### 6.1 升级方向一：分子缓存系统 + 任务目录重构

#### 6.1.1 目标

建立 **molecule-centered cache + task-centered projection** 双层结构。

#### 6.1.2 推荐目录结构

```text
output_root/
├── molecule_cache/
│   ├── <molecule_key>/
│   │   ├── s1/
│   │   ├── thermo/
│   │   └── metadata.json
├── reaction_cache/
│   ├── <step_key>/
│   │   ├── s2/
│   │   ├── s3/
└── tasks/
    ├── rx_0001/
    │   └── links_or_manifest.json
```

#### 6.1.3 Key 设计

```text
molecule_key = hash(canonical_smiles + stereo + charge + multiplicity)
cache_key    = hash(molecule_key + theory_signature)
```

#### 6.1.4 缓存优先级

| **优先级** | **缓存对象** | **收益** |
|---|---|---|
| P0 | S1 主分子（product / precursor） | 最大 |
| P1 | S2 step cache | 中 |
| P2 | S3 TS cache | 小 |

#### 6.1.5 外部参考

- **AiiDA**：`hash + cache version + input provenance`
- **QCArchive**：molecule hash 去重
- **RDKit RegistrationHash**：stereochemistry-aware 去重

#### 6.1.6 当前评价

> **V2.2 缓存升级的首要目标，不是继续强化 small molecule reuse，而是把主分子重复计算问题从根上解决。**

---

### 6.2 升级方向二：S4 特征提取与机理表达式升级

#### 6.2.1 目标

把 **S0 升级为机理表达层**，把 **S4 升级为配平热力学消费层**。

#### 6.2.2 S0 需要扩展的输出

```json
{
  "steps": [
    {
      "step_id": 1,
      "label": "dipole_generation",
      "reactants": [
        {"smiles": "...", "role": "precursor", "stoich": 1},
        {"smiles": "...", "role": "oxidant", "stoich": 1}
      ],
      "products": [
        {"smiles": "...", "role": "dipole", "stoich": 1},
        {"smiles": "...", "role": "byproduct", "stoich": 1}
      ],
      "equation": "precursor + oxidant >> dipole + byproduct"
    }
  ]
}
```

#### 6.2.3 S4 热力学公式升级

当前近似：

```text
ΔG_act ≈ G(intermediate) + G(leaving_group) - G(precursor)
```

V2.2 目标：

```text
ΔG_step1  = Σ G(products_of_step1) - Σ G(reactants_of_step1)
ΔG‡_step1 = G(TS1) - Σ G(reactants_of_step1)
```

#### 6.2.4 S4 新增字段建议

- `thermo.step1_dG_balanced`
- `thermo.step1_dG_activation_balanced`
- `thermo.oxidant_G_kcal`
- `thermo.byproduct_G_kcal`
- `mechanism.step1_equation`

#### 6.2.5 当前评价

> **V2.2 的关键不是在 S4 再补一个经验修正，而是把 S0 的机理表达真正接入 S4 的热力学消费逻辑。**

## 8. 总体评价

### 8.1 V2.1.0 已实现的核心成果

| **维度** | **V2.0 及之前** | **V2.1.0** |
|---|---|---|
| 机理处理 | 硬编码 / SMARTS 猜测 | S0 显式机理分类 |
| 构象搜索 | 单一流程 | 协议化 funnel（多模式） |
| TS 初猜 | 简单扫描 | `retro scan + path search + Gau_XTB` |
| 特征提取 | 固定输出 | 插件式挖掘系统 |

### 8.2 V2.2 必须解决的核心问题

1. **重复分子重复算** → 缓存系统  
2. **`dr` / 路径语义未进入主链** → 路径展开  
3. **S0 机理表达不够热力学完备** → 配平表达式  
4. **S4 第一步热力学不配平** → 平衡热力学  

### 8.3 最终判断

> **V2.2 的本质任务，是把 RPH 从"能搜到路径"升级为"能复用、能配平、能解释、能面向大数据集稳定抽取正确机理热力学特征"的平台。**
