# V7.1 特征提取增强方案 — intermediate 优先、TS 次级

**日期**: 2026-05-26
**范围**: `rph_features` 特征提取模块增强，聚焦中间体 (intermediate) 和过渡态 (TS) 特征
**结论**: intermediate 的优化几何、波函数、能量和元数据在特征提取阶段未被一等化——现有提取器只把 intermediate 当作 TS 特征的 fallback 输入。TS 已有基础几何/频率/能量特征，但缺少解释性元数据。

## 1. 前置条件 — 上游需要提供的数据

> **说明**: 以下修改在 `rph_core/`（RPH 主流程）中完成，目的是让 intermediate 的完整数据到达特征提取模块。这些是特征提取器工作的**数据就绪条件**，不属于特征提取方案本身。

### 1.1 当前数据流断点

| 数据 | 定义位置 | 是否传到提取器 | 影响 |
|------|----------|:---:|------|
| `intermediate_xyz` (S3 优化后的中间体几何) | `Step3Artifacts` 有字段 | ❌ `run_step3()` 未填充 | 几何类 intermediate 特征只能用 S2 原始 guess |
| `intermediate_l2_energy` | `Step3Artifacts` 有字段 | ❌ `run_step3()` 未填充 | intermediate 绝对能量不可提取 |
| `intermediate_opt_output` | `Step3Artifacts` 有字段 | ❌ 未传递 | intermediate 优化输出路径丢失 |
| `intermediate_sp_output` | `Step3Artifacts` 有字段 | ❌ 未传递 | intermediate SP 输出路径丢失 |
| `intermediate_fchk` | `Step3Artifacts` 有，已传递 | ✅ 部分 | 当前被 `step2_cyclization` 用作 CDFT fallback，但命名污染为 `s2_*` |
| `intermediate_log` | `Step3Artifacts` 有，已传递 | ✅ | 已在 FeatureContext 中 |
| `intermediate_qm_output` | `Step3Artifacts` 有，已传递 | ✅ | 已在 FeatureContext 中 |

### 1.2 需要补上的传递链路

**文件 A** — `rph_core/steps/step3_opt/ts_optimizer.py`

`TransitionAnalysisResult` 需新增 4 个字段并在 `run_with_qctaskrunner()` 返回时填充：

```
intermediate_xyz: Optional[Path]      # S3 优化后 / intermediate_driver 产出的 xyz
intermediate_l2_energy: Optional[float]
intermediate_opt_output: Optional[Path]
intermediate_sp_output: Optional[Path]
```

**文件 B** — `rph_core/steps/runners.py`

`run_step3()` 返回的 `Step3Artifacts(...)` 需填充这 4 个字段。

`run_step4()` 需接收并转发 2 个新参数：

```
s3_intermediate_xyz: Optional[Path]
s3_intermediate_l2_energy: Optional[float]
```

（`intermediate_opt_output` 和 `intermediate_sp_output` 可由 `s3_intermediate_xyz` 路径推导，暂不单独传递。）

**文件 C** — `rph_core/orchestrator.py`

`PipelineResult` 需新增字段 `s3_intermediate_xyz`, `s3_intermediate_l2_energy`，在 S3 完成后从 `step3_artifacts` 转存，并在调用 `run_step4()` 时传入。

注意保留现有 `intermediate_xyz`（S2 原始结构）不变——新增字段用 `s3_` 前缀与旧字段区分。

**文件 D** — `rph_features/rph_features/context.py`

`FeatureContext` 新增：

```python
s3_intermediate_xyz: Optional[Path] = None
s3_intermediate_l2_energy: Optional[float] = None
```

**文件 E** — `rph_features/rph_features/feature_miner.py`

`run()` 方法接受 `s3_intermediate_xyz` 和 `s3_intermediate_l2_energy` 并注入 `FeatureContext`。

### 1.3 前置条件验收

`feature_meta.json` 的 `artifact_presence` 中出现：

- `s3_intermediate_xyz`
- `s3_intermediate_l2_energy`

## 2. Intermediate 特征族 — 优先级 P0

> **目标**: 不依赖 Multiwfn，先用已有 XYZ / fchk / sp_report 构建稳定的 intermediate 基础特征。

### 2.1 新建提取器

**文件**: `rph_features/rph_features/extractors/intermediate_features.py`

**类名**: `IntermediateFeaturesExtractor`  
**插件名**: `intermediate_features`  
**注册**: `register_extractor(IntermediateFeaturesExtractor())` 在模块末尾

#### 2.1.1 几何特征 (`int_geom.*`)

| 特征列 | 含义 | 来源 |
|--------|------|------|
| `int_geom.rg` | intermediate 回转半径 (Å) | `s3_intermediate_xyz` 优先 → `intermediate_xyz` fallback |
| `int_geom.min_nonbonded` | 最小非键接触距离 (Å) | 同上 |
| `int_geom.close_contacts` | close contact 计数 (cutoff 2.2 Å) | 同上 |
| `int_geom.close_contacts_density` | close_contacts / natoms | 同上 |
| `int_geom.forming_distance_1` | forming bond 1 原子对在 intermediate 中的距离 (Å) | 同上 + `forming_bonds` |
| `int_geom.forming_distance_2` | forming bond 2 原子对在 intermediate 中的距离 (Å) | 同上 |
| `int_geom.asynch` | \|d1 − d2\| | 同上 |
| `int_geom.rmsd_to_s2_guess` | S3 优化 intermediate 与 S2 guess 的 RMSD (Å) | `s3_intermediate_xyz` vs `intermediate_xyz` |
| `int_geom.source` | 几何数据来源标签 | `s3_intermediate_xyz` / `s2_intermediate_fallback` / `missing` |

**Degradation 策略**:
- `s3_intermediate_xyz` 缺失但 `intermediate_xyz` 存在 → 降级使用 S2 原始结构，`int_geom.source = s2_intermediate_fallback`
- 两者均缺失 → 所有列为 NaN，状态 degraded

#### 2.1.2 能量特征 (`int_energy.*`)

| 特征列 | 含义 | 来源 |
|--------|------|------|
| `int_energy.l2_hartree` | intermediate L2 单点能 (Hartree) | `s3_intermediate_l2_energy` 优先 → `sp_report.e_reactant` |
| `int_energy.rel_to_product_kcal` | E(int) − E(product)，正值表示 intermediate 能级高于产物 | `sp_report.e_reactant` − `sp_report.e_product` |
| `int_energy.rel_to_ts_kcal` | E(TS) − E(int)，正值为能垒 | `sp_report.e_ts_final` − `sp_report.e_reactant` |

> 这些列与现有 `thermo.dE_activation` 在数值上等价，但命名更明确、便于 ML 解释。

#### 2.1.3 电子结构特征 (`int_cdft.*`)

| 特征列 | 含义 | 来源 |
|--------|------|------|
| `int_cdft.eps_homo` | intermediate HOMO (eV) | `intermediate_fchk` → `read_fchk_cdft_indices()` |
| `int_cdft.eps_lumo` | intermediate LUMO (eV) | 同上 |
| `int_cdft.mu` | 化学势 (eV) | 同上 |
| `int_cdft.eta` | 化学硬度 (eV) | 同上 |
| `int_cdft.omega` | 亲电指数 (eV) | 同上 |
| `int_cdft.gap` | HOMO-LUMO gap (eV) | 同上 |

> 复用现有 `rph_core/utils/fchk_reader.py` 的 `read_fchk_cdft_indices()`，不重复实现。
> 这些值当前被 `step2_cyclization` 提取但命名在 `s2_*` 下。新增列 `int_cdft.*` 后，旧 `s2_*` 保留兼容但不作为 intermediate 的推荐消费路径。

**Degradation**: `intermediate_fchk` 缺失 → 全部 NaN，记录 warning `W_INT_MISSING_FCHK`。

#### 2.1.4 电荷特征 (`int_charge.*`)

| 特征列 | 含义 | 来源 |
|--------|------|------|
| `int_charge.fragment_a` | fragment A 净电荷 (e) | `intermediate_fchk` + `cut_along_forming_bonds()` |
| `int_charge.fragment_b` | fragment B 净电荷 (e) | 同上 |
| `int_charge.delta_frag` | fragment A − B 电荷差 (e) | 同上 |
| `int_charge.forming_atom_a` | forming bond 原子 A 的原子电荷 (e) | `intermediate_fchk` → 原子电荷 |
| `int_charge.forming_atom_b` | forming bond 原子 B 的原子电荷 (e) | 同上 |

> 复用现有 `rph_core/utils/fragment_cut.py` 和 `rph_core/utils/charge_reader.py`。

**Degradation**: forming bonds 缺失或片段切割失败 → 列为 NaN。

### 2.2 在 extractors 注册表中激活

`rph_features/rph_features/extractors/__init__.py` 增加一行：

```python
from . import intermediate_features
```

### 2.3 验收

- `features_raw.csv` 中出现 `int_geom.*`, `int_energy.*`, `int_cdft.*`, `int_charge.*` 列
- `s3_intermediate_xyz` 缺失时 `int_geom.source = s2_intermediate_fallback`
- 所有列均使用 `int_*` 点号前缀，不与现有 `s2_*` / `mw_*` / `geom.*` 冲突

## 3. Intermediate Multiwfn 波函数特征 — 优先级 P1

> **目标**: 在 intermediate fchk 可用时，利用 Multiwfn 提取 Fukui、Dual Descriptor、QTAIM BCP 等局部反应性描述符。

### 3.1 现状

现有 `multiwfn_features.py` 硬编码只分析 TS fchk：

```python
# multifeatures_extractor.py 第 114 行
ts_fchk = context.s3_ts_fchk        # ← 只取 TS
```

`MultiwfnRunner`（`rph_core/utils/multiwfn_runner.py`）是通用的，可以处理任意 fchk。但有一个已知问题：`run_complete_analysis()` 把同一解析结果复制给 atomA 和 atomB，未真正区分两个原子的值。

### 3.2 方案 — 独立提取器

**不在** `multiwfn_features.py` 中作修改。新建独立文件：

**文件**: `rph_features/rph_features/extractors/intermediate_multiwfn.py`

**类名**: `IntermediateMultiwfnExtractor`
**插件名**: `intermediate_multiwfn`
**注册**: `register_extractor(IntermediateMultiwfnExtractor())` 在模块末尾

**原因**:
- TS `mw_*` 语义已被 schema、数据集和 ML 管线消费，改动风险高
- intermediate 的 degradation 行为不同：forming BCP 不存在是正常化学现象
- 独立提取器可以单独配置启用/禁用

### 3.3 提取内容

| 特征列 | 含义 | Degradation 行为 |
|--------|------|-----------------|
| `int_mw_fukui_fplus_atomA` | forming atom A electrophilic Fukui (e) | fchk 缺失 → NaN |
| `int_mw_fukui_fplus_atomB` | forming atom B electrophilic Fukui (e) | fchk 缺失 → NaN |
| `int_mw_fukui_fminus_atomA` | forming atom A nucleophilic Fukui (e) | 同上 |
| `int_mw_fukui_fminus_atomB` | forming atom B nucleophilic Fukui (e) | 同上 |
| `int_mw_fukui_f0_atomA` | forming atom A radical Fukui (e) | 同上 |
| `int_mw_fukui_f0_atomB` | forming atom B radical Fukui (e) | 同上 |
| `int_mw_dual_descriptor_atomA` | forming atom A dual descriptor (e) | 同上 |
| `int_mw_dual_descriptor_atomB` | forming atom B dual descriptor (e) | 同上 |
| `int_mw_rho_bcp_forming1` | forming contact 1 BCP ρ (au) | BCP 不存在 → NaN (非错误) |
| `int_mw_rho_bcp_forming2` | forming contact 2 BCP ρ (au) | 同上 |
| `int_mw_laplacian_bcp_forming1` | forming contact 1 BCP ∇²ρ (au) | 同上 |
| `int_mw_laplacian_bcp_forming2` | forming contact 2 BCP ∇²ρ (au) | 同上 |
| `int_mw_status` | ok / disabled / degraded / failed | — |
| `int_mw_missing_reason` | 缺失原因码 | — |
| `int_mw_warnings_count` | 警告计数 | — |

### 3.4 输入

- `context.intermediate_fchk` (优先 `s3_intermediate_fchk`, 回退 `intermediate_fchk`)
- `context.forming_bonds`

### 3.5 需要先行的 MultiwfnRunner 修复

实施 intermediate Multiwfn 前，`MultiwfnRunner` 需修正：

1. **atomA/atomB 值独立化** — 当前 parser 对两个 atom 返回同一值。需要确认 Multiwfn 脚本是否正确输出两个原子的独立数值，或分别针对每个原子运行两次。
2. **cache key 完整化** — 需包含 input_file sha256、module 名、atom pair、Multiwfn version、script version。
3. **QTAIM BCP 对 nonbonded contact 的容错** — 返回值允许为 None/NaN，不标记为整个分析的失败。

### 3.6 在 extractors 注册表中激活

```python
from . import intermediate_multiwfn
```

### 3.7 验收

- Multiwfn disabled 时 `int_mw_status = disabled`
- intermediate fchk 存在时产出 Fukui/Dual Descriptor 数值
- forming BCP 不存在时 `int_mw_rho_bcp_* = NaN`, `int_mw_status` 不为 failed
- 不破坏现有 `mw_*` 列

## 4. TS 解释性增强 — 优先级 P2

> **目标**: 在已有 `geom.*`, `thermo.dE_*`, `ts.n_imag`, `ts.imag1_cm1_abs` 的基础上，增加能量拆分、虚频模式解释、优化难度和 rescue 元数据。

### 4.1 扩展 `ts_quality.py`

现有输出: `ts.n_imag`, `ts.imag1_cm1_abs`, `ts.dipole_debye`

**新增列** (保留旧列兼容):

| 特征列 | 含义 | 来源 |
|--------|------|------|
| `ts_freq.n_imag` | 虚频数量 | ts_log |
| `ts_freq.imag_cm1` | 虚频波数 (带符号) | ts_log |
| `ts_freq.imag_abs_cm1` | 虚频绝对值 | ts_log |
| `ts_freq.mode_overlap_forming` | 虚频模式矢量与 forming bond 矢量的重叠 (0-1) | ts_log normal mode + forming_bonds |
| `ts_freq.has_single_imag` | n_imag == 1 的布尔标志 | ts_log |

> `mode_overlap_forming` 是 TS 质量的关键指标：值接近 1.0 说明虚频确实对应反应坐标，值低则 TS 可能不正确。

### 4.2 新建 `ts_optimization_metadata.py`

**文件**: `rph_features/rph_features/extractors/ts_optimization_metadata.py`

**类名**: `TSOptimizationMetadataExtractor`
**插件名**: `ts_optimization_metadata`

读取 S3 目录下的元数据文件：

| 特征列 | 含义 | 来源 |
|--------|------|------|
| `ts_opt.method_used` | Berny / QST2 / Intermediate_Reuse | `s3_resume.json` → `ts_opt.method_used` |
| `ts_opt.rescue_attempted` | 是否触发救援策略 (0/1) | `s3_resume.json` |
| `ts_opt.rescue_route` | 救援路径 (qst2 / oscillation / none) | `s3_resume.json` |
| `ts_opt.failure_kind` | 失败类别 (oscillation / convergence / none) | `s3_resume.json` |
| `ts_opt.n_cycles` | 优化循环数 | ts_log convergence table |
| `ts_opt.converged` | 最终收敛标志 (0/1) | ts_log |
| `ts_opt.has_l2_sp` | L2 单点是否完成 (0/1) | artifact presence |
| `ts_opt.has_freq` | 频率分析是否完成 (0/1) | artifact presence |

**输入**: `context.s3_dir` → 读取 `s3_resume.json`, `.rph_step_status.json`, `sp_matrix_metadata.json`, ts_log。

**Degradation**: `s3_dir` 缺失 → 全部列为 NaN/unknown。

### 4.3 能量拆分列

在 `thermo.py` 或 `intermediate_features.py` 中新增显式的能量关系列：

| 特征列 | 含义 | 公式 |
|--------|------|------|
| `ts_energy.l2_hartree` | TS L2 单点能 | `sp_report.e_ts_final` |
| `ts_energy.rel_to_intermediate_kcal` | E(TS) − E(int) | 与 `thermo.dE_activation` 等价 |
| `ts_energy.rel_to_product_kcal` | E(TS) − E(product) | `sp_report.e_ts_final` − `sp_report.e_product` |
| `int_energy.rel_to_product_kcal` | E(int) − E(product) | `sp_report.e_reactant` − `sp_report.e_product` |

> 这些是现有 `thermo.*` 的显式拆分，不替代旧列。

| 6 | **特征族与 dataset 集成** | `schema.py`, `dataset_builder.py` | branch 层出现 major/minor/delta/abs_delta intermediate 特征 |

## 7. 风险与约束

1. **Multiwfn 输出解析脆弱**
   现有 parser 使用正则匹配 stdout，未按 atom 区分。实施前需用固定 sample fchk 固化 Multiwfn 输出样例，写死 parser 的预期格式。

2. **Intermediate forming contact BCP 不稳定**
   反应前两个 forming bond 原子之间的距离 (3-6 Å) 可能没有 BCP。QTAIM 分析必须是 optional 模块，BCP 不存在 → NaN，不可作为整个提取器失败的条件。

3. **S2 intermediate vs S3 optimized intermediate 命名**
   必须显式区分两者。`intermediate_xyz` 永远是 S2 原始 guess；新增 `s3_intermediate_xyz` 是 S3 优化后的。特征提取器应优先用 `s3_intermediate_xyz`，并在 source 字段中标记实际使用的数据来源。

4. **ML schema 膨胀**
   新增约 50 列。所有列先进入 `features_raw.csv`；`features_mlr.csv` 默认列保持保守，仅增加已验证有信号的列。

5. **提取阶段不运行新 QC**
   特征提取阶段是 extract-only。Multiwfn 作为外部波函数分析工具，必须遵循 `job_run_policy: disallow` 的默认策略——只读已有 fchk 文件。如需启用 Multiwfn 分析，需明确在 config 中配置。

6. **现有 `s2_*` CDFT 列与新增 `int_cdft.*` 的关系**
   当前 `step2_cyclization` 提取的 CDFT 来自 `intermediate_fchk or ts_fchk`，但列名在 `s2_*` 下。新增 `int_cdft.*` 后两者会并存但值可能不同（因为数据源优先级不同）。建议在文档中标明 `int_cdft.*` 是推荐的 intermediate 电子结构消费路径。
