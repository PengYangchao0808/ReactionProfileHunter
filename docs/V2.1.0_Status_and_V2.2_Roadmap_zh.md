# ReactionProfileHunter V2.1.0 状态总结与 V2.2 路线图

> 更新日期：2026-04-12  
> 用途：阶段总结 / docs 首页索引 / 汇报摘要版

---

## 1. 当前状态概览

ReactionProfileHunter（RPH）当前已经形成完整的 product-driven 反应机理搜索与特征提取主链：

```text
输入 SMILES / 数据集记录
    → S0 机理分类
    → S1 多构象锚定
    → S2 逆向扫描与 TS 初猜
    → S3 TS 优化 / 验证
    → S4 特征提取
```

V2.1.0 的核心增量主要集中在以下三点：

1. **S0 机理分类落地**
2. **S1 协议化多构象搜索落地**
3. **S2 稳定 TS 初猜链路落地**

---

## 2. V2.1.0 三项核心成果

### 2.1 S0：机理分类

- 将 `forming_bonds` 从猜测逻辑前移为显式机理前置步骤
- 已支持 `[4+3]`、`[5+2]`、`[4+2]`、`[3+2]`
- 当前已具备成键拓扑级分类能力

**当前边界：**

- 还没有完整配平机理表达
- 还没有显式 `oxidant / byproduct / stoichiometry` 语义

---

### 2.2 S1：协议化多构象搜索

已支持多种预算等级协议：

| **协议** | **说明** |
|---|---|
| `ext / default` | 两阶段 CREST + 全量 handoff |
| `full` | GFN2 + 双 fast-SP funnel |
| `lite` | GFN2 + screening funnel |
| `zero` | GFN2 + 最低成本 funnel |

**已实现价值：**

- 搜索协议显式化
- funnel 与 handoff 分离
- 同一引擎承载多成本模式

**当前边界：**

- 仅 small molecule 有缓存
- 主分子仍存在大量重复计算

---

### 2.3 S2：逆向扫描稳定 TS 搜索

S2 当前核心链路为：

```text
S0 forming_bonds
    ↓
retro scan
    ↓
knee-point TS 检测
    ↓
topology guard
    ↓
Gau_XTB / path search
    ↓
S3
```

**当前已实现：**

- product-driven outward retro scan
- knee-point TS 候选识别
- 轨迹拓扑守卫
- Gau_XTB 预优化
- path search 互补增强

**意义：**

- 显著提升 TS 初猜稳定性
- 成为 RPH 当前能稳定进入 S3 的关键基础

---

## 3. 当前主要短板

### 3.1 重复分子重复算

当前目录仍以 `rx_id` 为中心，导致同一数据集中大量重复主分子反复跑 S1 / S2 / S3。

### 3.2 `dr / ee` 未进入主流程

虽然数据层已经解析 `ee`、`dr_major`、`dr_minor`，但主机理与路径搜索链条尚未显式消费这些信息。

### 3.3 S0 机理表达不完整

S0 当前能输出 `forming_bonds`，但还不能输出：

- 完整 step-wise reactants / products
- `oxidant / byproduct / catalyst` 角色
- 平衡反应表达式
- `stoichiometry`

### 3.4 S4 第一步热力学不配平

当前 S4 对第一步活化热力学的近似仍偏向：

```text
G(intermediate) + G(leaving_group) - G(precursor)
```

对 DMDO 等体系，无法正确考虑：

- oxidant 消耗
- acetone 等副产物生成
- 多碎片热力学闭合

## 4. V2.2 升级重点

### 4.1 方向一：缓存系统与目录重构

目标：

- 建立 `molecule-centered cache`
- 建立 `task-centered projection`
- 让相同分子只算一次，让不同任务共享缓存

建议结构：

```text
output_root/
├── molecule_cache/
├── reaction_cache/
└── tasks/
```

---

### 4.2 方向二：S0 → S4 机理表达与平衡热力学升级

目标：

- S0 输出完整机理步骤表达
- S4 消费平衡热力学，而非局部经验近似

建议新增的 `mechanism_summary.json` 结构：

```json
{
  "steps": [
    {
      "step_id": 1,
      "reactants": [
        {"smiles": "...", "role": "precursor", "stoich": 1},
        {"smiles": "...", "role": "oxidant", "stoich": 1}
      ],
      "products": [
        {"smiles": "...", "role": "dipole", "stoich": 1},
        {"smiles": "...", "role": "byproduct", "stoich": 1}
      ],
      "equation": "precursor + oxidant >> dipole + byproduct"
    }
  ]
}
```

## 6. 总体判断

V2.1.0 已经完成了从"产物驱动脚本"到"机理感知流水线"的关键转型。  
V2.2 的核心任务则是进一步解决四个问题：

1. **复用**：避免重复分子重复计算  
2. **配平**：建立完整机理表达与 step-wise 热力学  
3. **解释**：让 S4 特征真正反映化学过程  
4. **扩展**：让大数据集批处理可持续运行  

> **一句话总结：V2.2 不是简单加功能，而是让 RPH 从"能跑"升级到"能复用、能配平、能解释"。**
