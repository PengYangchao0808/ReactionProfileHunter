🔍 计划遗漏的隐藏问题

主动审计发现的 16 项计划未覆盖的问题
#H-01
executables: null 时 15+ 处调用崩溃
CRITICAL 计划遗漏

详见 最高优先级发现 章节。15 个未保护的 .get('executables', {}).get(...) 调用点。

#H-02
_inherit_if_null 对 nproc=0 不触发继承
HIGH 计划遗漏

位置：resource_utils.py:656-663

def _inherit_if_null(config, key_path, default):
    ...
    if d.get(parts[-1]) is None:  # ← 0 is None → False
        d[parts[-1]] = default

影响：用户配置 theory.optimization.nproc: 0（笔误或想表示"自动"）时，继承被跳过，nproc 保持 0，下游除法运算可能抛 ZeroDivisionError。

建议：检查条件改为 if d.get(parts[-1]) in (None, 0, ""):。

#H-03
_resolve_mpi 写回在 orca 子键缺失时丢失
HIGH 计划遗漏

位置：resource_utils.py:349, 360-361

orca_cfg = config.get('executables', {}).get('orca', {})  # ← 临时 {} 不写回
...
orca_cfg['mpi_bin_dir'] = str(Path(val))  # ← 写到临时 dict
orca_cfg['mpi_lib_dir'] = str(Path(val).parent / 'lib')

陷阱：当 executables.orca 在 YAML 中不存在时，.get('orca', {}) 返回新建的临时 dict，对它的修改不会持久化到 config。_build_orca_runtime_env（orca_interface.py:774）后续读取 config 找不到 MPI 路径 → 回退到硬编码候选。

建议：在 _resolve_mpi 开头加 config.setdefault('executables', {}).setdefault('orca', {})。

#H-04
setup_ld_library_path 全局环境变量污染
MEDIUM 计划遗漏

位置：resource_utils.py:207

os.environ['LD_LIBRARY_PATH'] = new_path  # ← 全局副作用

影响：每次调用 resolve_executable_config（针对含 ld_library_path 的程序）都会原地修改全局 os.environ。多次调用会累积路径，无清理机制。多进程模式下安全（每个 worker 各自 init），但函数不可重入、不可逆。

建议：返回 dict 而非原地修改；由调用方决定是否设到 os.environ。

#H-05
GAUSS_SCRDIR 被 sandbox 强制覆盖到 /tmp
MEDIUM 计划遗漏

位置：qc_interface.py:845-847, 920-921

# L847：从 config 读取 scratch_dir

    env['GAUSS_SCRDIR'] = str(scratch)

# L921：sandbox 强制覆盖

#H-12

#H-15

resolve_resources 和 normalize_qc_config 在 ReactionProfileHunter.__init__ 内调用，batch 模式下每个 worker 进程独立构造 → 突变隔离。已确认安全。

⚠️ 计划不准确之处

修复计划中描述与实际代码不完全吻合的 2 处
#I-01
ORCAInterface._find_orca_binary 实际已调用 resolve_executable_config
计划不准确

计划声明（P1-A）：_find_orca_binary() 中有"二次 shutil.which("orca") fallback"需要删除。

实际代码（orca_interface.py:725-762）：

751exe_config = resolve_executable_config(config, 'orca', env_vars=['ORCA_PATH', 'ORCA_BIN'])
752if exe_config.get('found'):
753    return exe_config['path']
754
756orca_cmd = shutil.which('orca')  # 这是第 3 步独立 fallback
757if orca_cmd:
758    return Path(orca_cmd)

结论：ORCA 实际已使用统一解析函数，只是在其之后又加了一道 shutil.which。计划"完全没委托"的描述不准确 —— 应改为"已部分委托但仍有冗余 fallback"。

#I-02
_inherit_if_null 描述含小细节错误
计划不准确

计划相关描述暗示 _inherit_if_null 在键缺失时不触发。

实际：d.get(parts[-1]) 在键缺失时返回 None，None is None 为 True，会触发继承。所以"键缺失"和"值为 None"行为一致；只有值为 0、False、"" 等非 None falsy 值时不触发。

影响：行为总体合理，但 0 值的特殊处理仍需关注（见 #H-02）。
