## 1. 报告摘要

V2.1.0 当前已经完成了 S1 四协议体系从“协议可解析、handoff 可执行”到“协议分层可在真实运行中观测”的关键跨越。

本轮状态可以概括为：

1. **四协议均已真实可运行**：`ext / full / lite / zero` 均能完成 S1 产物锚定。
2. **shared DFT handoff 已稳定建立**：四协议最终统一交付 DFT-level 工件给后续 S2/S3/S4。
3. **funnel 层级差已经开始落地**：
   - `ext`：两阶段 `GFN0 -> GFN2`
   - `full`：`GFN2 + prescreen_sp(PBEh-3c) + screening_sp(r2SCAN-3c)`
   - `lite`：`GFN2 + screening_sp(r2SCAN-3c)`
   - `zero`：`GFN2 cheapest funnel`
4. **动态 handoff 元数据链路已打通**：`mode_requested / mode_effective` 已可在 provenance 与测试脚本中观察。
5. **关键回归门已通过**：Step1 / S4 / chain tests 全部通过，且四协议实跑脚本已验证通过。

> **S1 的 protocol-specific funnel runtime 已经落地并可运行，但 full 的近似自由能排序（mRRHO）以及 lite/zero 的动态 fallback 分支还需要用更具区分度的样本进一步覆盖验证。**

## 5. 为什么 lite 比 zero 只慢了约 36.6 秒？

本次实测：

- `lite = 1593.9 s`
- `zero = 1557.3 s`
- 差值：**36.6 s**

这并不表示 `lite` 的 screening SP 没起作用，而是说明：

> **在这个测试分子上，主导 wall time 的主要部分不是 lite 多出来的 screening-level fast-SP，而是两者都共享的最终 DFT handoff。**

### 原因拆解

#### lite

- CREST + ensemble：约 `428 s`
- 额外 `r2SCAN-3c` screening SP（2 个构象）：约 `53 s`
- 最终 Gaussian OPT/FREQ + ORCA final SP：约 `1112 s`

#### zero

- CREST + ensemble：约 `447 s`
- 额外 fast-SP：无
- 最终 Gaussian OPT/FREQ + ORCA final SP：约 `1109 s`

### 解释

1. `lite` 确实增加了 screening-level fast-SP 成本（约 50 s 量级）
2. 但 `zero` 这次本身的 GFN2 搜索略慢一些
3. 更关键的是：
   - 两者最终都只保留了 **1 个构象**
   - 两者都走了**同一套昂贵的 DFT handoff**

因此总 wall time 会非常接近。

### 本质结论

这恰恰反映了当前架构设计的意图：

> **四协议的差异在 funnel 等级，不在最终 handoff 数据层级。**

所以当某个样本上：

- lite 最终只剩 1 个构象
- zero 最终也只剩 1 个构象

那么两者的 wall time 很接近是正常结果，不是 bug。

### 什么时候差异会拉大？

只有在以下情形下，lite 与 zero 的成本差才会明显放大：

1. `lite` 在 funnel 末端保留多个候选并触发 `top2 fallback`
2. `zero` 的 0.5 kcal/mol 窗口内出现多个 survivor，从而触发 `optimize_all_within_0p5_kcal`
3. 测试分子更复杂，使 funnel 阶段成本不再被最终 shared DFT handoff 完全淹没
